Retrieval-augmented QA over real contracts

Ask a contract.
Get the clause.

contract-rag reads real commercial contracts, searches inside the one you ask about, and answers with a citation to the clause it came from. Every part of it was measured: 189 search setups, 560 graded answers, and a hand-read diagnosis of what goes wrong.

Everything between a PDF and a trustworthy answer

Six stages, each one built so it can be switched out and measured.

Here's how it works…

One question, from a scanned-looking PDF to a checked answer.

  1. Read the contract like a lawyer's PDF

    Layout-aware parsing finds headings by font size and weight, keeps tables as tables, and records where every character came from.

  2. Search inside that one contract

    BM25 keyword search over 512-token chunks, with the contract's own name taken out of the question so it can't drown out the meaning.

  3. Answer only from what was found

    The eight best excerpts are numbered; the model must cite them, like [5], or say the contract doesn't cover it.

  4. Check every sentence

    A second model checks each claim against only the excerpts it cites, and grades the answer against a lawyer's reference.

Ask it something

Real questions and real answers from the test run. Click a citation to see the exact sentence it points to.

These answers were generated and graded offline (fixed chunks + BM25, the best setup). Typing your own question needs the API, which is the next part of the project.

What the experiments found

Chosen on the dev questions, reported on 70 held-out test questions, with 95% confidence intervals throughout.

Search.

Inside one contract, plain keywords win.

189 search setups were scored: three ways to cut a contract, BM25, three local embedding models, two ways to combine them, and two rerankers.

  • Dropping the contract's own name from the question more than doubled how high the right clause ranks.
  • Meaning search alone was significantly worse than keywords; combining them tied.
  • The larger reranker hurt, and cost about a second per question.

Answer.

Most answers are right, and all of them cite.

Eight setups were run end to end: qwen3.5:4b answers from numbered excerpts, and gemma4:12b grades them.

  • Correctness lands between 0.65 and 0.75 for every setup; the differences are within noise.
  • Answers from section or sentence-window excerpts stick closest to their sources (0.83–0.87 faithful).
  • On questions the contract can't answer, it says so 91% of the time.

Grade.

We checked the checker.

The first grader marked answers wrong for true details that weren't in the lawyer's highlighted clause. Every fix to the grader had to agree better with 24 reference labels before it was allowed in.

  • A stricter-looking "checklist" grader agreed worse and was rejected.
  • The adopted rule: extra details only count against an answer if they contradict the reference.

Diagnose.

Every wrong answer, traced to where it broke.

Each of the 185 answers that weren't fully correct was followed through the saved pipeline data to the first stage that failed, and 20 were read by hand.

  • 62% fail before the model sees the evidence, mostly two-part questions where only one part's clause is found.
  • Missed clauses share far fewer words with the question: 12% vs 34%.
  • With the evidence in hand, the 4B model still slips: inverted rights, merged clauses, wrong citation numbers.
